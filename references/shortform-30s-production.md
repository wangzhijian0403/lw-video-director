# LW Video Director · 30 秒短片制作与验收协议（v0.3.0-preview.1）

> **范围**：新的独立题材、25–35 秒高质量知识讲解/MG 成品；优先验证“能否复用 Skill”，不再返修《造纸术》。此文件定义制作流程与验收要求，**不代表一键自动化已经实现**。首轮默认 16:9、1920×1080、30fps。

## 1. 执行原则

- 用全新题材测试跨题材复用；不拿《造纸术》的文字、纸浆、水槽、青山画面换标签来凑片。
- 先内容，后画面：每镜必须回答“解释了什么”；禁止无关 3D、随机图表、静态 PPT + 缩放。
- 目标约30秒，建议 5–7 镜，3–6 秒/镜；时长以实测人声为准，25–35秒内调整，不裁切完整语句。
- 用户无新风格要求时，可采用清爽青灰蓝＋深青/宣纸白编辑风格，**不强行套《造纸术》的薄雾青山**。主题用 Token 控制，不用整张效果预览图当背景。
- 允许实拍、SVG 图标、外部插画、2.5D 分层、内容图表、形态连续转场及少量静态素材混用。每个外部资源单独登记源码和媒体许可。
- 新组件必须在可编辑工程中真实运行，不能以官方预览片或截图冒充源码接入。
- 新项目独立目录、素材和输出；保留旧《造纸术》工程，不覆盖，未经允许不公开发布。

- 字体、图片、音乐、音效及第三方组件代码按各自独立许可核查。

## 3. 三阶段交付

### A：内容与设计（短报告）

一页脚本与镜头表：每镜口播、表达目的、视觉媒介、组件及其可执行状态、素材来源、音效点、转场语义关联。不能生成无依据的数据比例、虚构事实或与口播无关的动画。

### B：真实 30 秒成片

1. 新建独立 project.json，遵守 visual-studio/src/project/types.ts 的字段；读 references/production-pipeline.md，不猜测接口。
2. 先合成/导入合法人声并实测时长，依真实音频配镜头和句级 SRT；不得根据字数伪造时码。
3. 用真实 Remotion MG/视频素材完成全片；至少两处有意义的跨镜内容转场。静止可存在，但必须有明确叙事目的。
4. 至少选用一组已获授权的外部 SVG 图标、精致插画、Lottie 或素材镜头（题材实在不适用则写出理由）；不允许全片依赖手写简陋几何。
5. 关键动作须有对应音效事件；人声优先、BGM自动避让。合成提示音不冒充真实拟音。
6. 在 visual-studio 下运行 npm ci、npm run lint:project、npm run build 或 npm test；使用 npm run direct 渲染实际 H.264 MP4。渲染命令参数以 scripts/direct.mjs 当前源码为准。
7. 检查首3秒、全镜转场接缝、手机缩放字幕、结尾2秒、音效与动作点。机器 QA 不能代替视觉验收。

### C：Skill 沉淀与复用证明

必须区分“做成了视频镜头”和“做成通用组件”。每项新效果记录：
- 组件/动画 ID、输入参数、目录、来源/版权、实际调用方法。
- 用第二套不同文案或素材做实际替换/渲染测试。没通过则标“项目专用”，不可宣称通用。
- 哪些自动执行、哪些仍需人工素材/授权/审片。
- 相关改动进入单独 Draft PR，未经审核不合并 main，不覆盖旧成片。

## 4. 成片验收硬条件

| 维度 | 最低要求 |
|---|---|
| 视频 | 1920×1080 / 30fps / 25–35秒，无黑帧、畸变、长期空白或严重压缩 |
| 视觉 | 统一设计系统；至少3种与内容相关且结构不同的动态图形表达；非PPT轮播 |
| 素材 | 至少一组许可明确的外部SVG/插画等合法素材（不适用则说明） |
| 转场 | 至少两处前后语义、形状或方向连续的内容驱动交接 |
| 音频 | 真实人声、音效与动作同步、必要BGM避让、可核查音效事件表与分轨 |
| 字幕 | 中文易读，不截字、不盖主体；实际时码来源可追溯 |
| 版权 | 代码、字体、图片、SFX、BGM分开记录允许使用范围 |
| 工程 | 完整工程JSON、实际素材、命令、源码commit、QA日志、最终MP4 |
| 质量 | 由独立审片人/用户作最终审美判断；技术PASS不等于视觉合格 |

## 5. 避免无限返工

先做一版完整短片及一次明确问题的局部返修。如果某镜两轮仍失败，应替换组件或设计，不再盲目加粒子。单件素材缺失不得阻塞整片，使用权利明确的合适替代方案。若关键输入缺失，准确说明阻塞，不伪造 TTS/授权/画面质量。

## 6. 最终交付

- **观看交付**：完整约30秒MP4、镜头总览图、声音分轨。
- **工程交付**：工程配置、来源素材与许可、真实QA、能力清单（沿用/新增通用/项目专用/未完成）。

通过上述验收后，再讨论把预览版升级为正式稳定发行版。
